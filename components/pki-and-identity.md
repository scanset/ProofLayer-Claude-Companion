# PKI & Identity

**Status: built.**

## What it is

Prooflayer is its own certificate authority. A scan result is only a *proof*
because the key that signed it chains back to a known root and is logged. The
hierarchy (generated by the PKI bootstrap script at first boot):

```
Root CA            self-signed, 10y, no pathlen limit      ← key kept offline in prod
  └─ Issuing Authority (IA)   pathlen:1, 1y                ← loaded at server start
        ├─ Workload CA        (in-memory, at startup)        → scanner identity cert
        └─ Log-signing cert   (in-memory, at startup)        → signs transparency checkpoints
```

Only the **Root** and **IA** key/cert pairs live on disk (`/opt/prooflayer/pki/`).
The segment CA, the scanner identity, and the log-signing cert are all minted
**in memory** from the IA at server startup — nothing else is persisted.

## The scanner identity (agentless signing)

In agentless mode the server signs its own scans. At boot it generates an
ECDSA-P256 keypair, builds a CSR with SAN
`esp://prooflayer/<deployment_name>/scanner`, has the IA issue a ~90-day
workload cert, and **appends that cert to the transparency log** — from the
log's perspective the scanner is "just another logged signing identity." Every
in-process scan envelope is then (re-)signed with this identity and carries its
cert chain + inclusion proof.

At ingest the server swaps the engine's own software signature for the
IA-anchored scanner-identity signature, so every stored envelope is anchored to
the published PKI rather than to an unrooted engine key.

## How signing produces a proof

```
scan runs → envelope built → signed by the scanner identity (ECDSA-P256)
          → signer cert appended to / already in the transparency log
          → envelope carries: signature, public key, cert chain, inclusion proof
```

An auditor reading one isolated envelope can: verify the signature, walk the
chain to the root, and check the inclusion proof against the log — without any
out-of-band registry.

## Alpha caveats

Self-signed root, generated at first boot. The eval container serves plain HTTP
(nginx does not terminate TLS), so this PKI exists to sign scan envelopes and
the transparency log — not to secure the browser connection. Non-FIPS dev build
(production links FIPS 140-3 OpenSSL; all crypto in the server already routes
through OpenSSL, no pure-Rust crypto). Cert auto-renewal is deferred — a 90-day
cert covers evaluation, and restart re-issues.
